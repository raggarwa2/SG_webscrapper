# First-view summary: build spec (no LLM, no tokens)

For the app that runs after a scrape. One script reads the scraped item table, writes one summary file, and a page renders it. No API calls anywhere.

## 1. Input contract

One row per scraped item (comment, review, post, ad). Map every new scrape into these columns first; everything below reads only these.

| Column | Type | Used for | Notes |
|---|---|---|---|
| `item_id` | text | de-duplication | unique per item |
| `source` | text | channel (Instagram, Reddit, Google Maps...) | |
| `lens` | text | grouping of sources (consumer voice, retail, app, brand broadcast) | optional; if missing use `source` |
| `brand_std` | text | brand / entity compared | blank allowed |
| `date` | text, ISO | trends | blank allowed |
| `text_en` | text | keyword scan | |
| `rating_native` | float | rating view | blank allowed (about 57% in the SG data) |
| `likes` | float | engagement view | blank allowed |
| `url` | text | "open" links | blank allowed (about 43%) |
| `lang_guess` | text | language share | |
| `is_contest` | 0/1 | giveaway filter | drop these rows from every count |

Source table in this project: `Scripts/output/voice_items_sg.db`, table `voice_items` (11,103 rows).

## 2. Global rules (apply to all five views)

- **Filter first:** drop `is_contest = 1`, drop duplicate `item_id`, then record how many were removed. Show the removed count on the page.
- **Thin data:** a rate or percentage needs a base of 15 items (`MIN_N`); under it show a dash. A bar needs 10 items (`MIN_COUNT`); under it do not draw it, list it as a count in a note. Bars of 10 to 29 are hatched (directional).
- **Sample-size strip:** under every chart, one line: `n = <items> across <sources> sources, <date range>`.
- **Charts shown, tables on click:** every chart is visible; its table sits in a collapsed "Show data" block with a CSV download.
- **Click-through:** where a bar stands for items, clicking it opens a list: text (first 200 characters), source, date, link ("open").
- **Label:** a badge at the top of the page: "Pre-tagging view. Counts, ratings and keyword matches only. Sentiment and themes come after model tagging."
- **Colours:** series in order `#178197`, `#0A7CC1`, `#A51890`, `#051F4A`, `#59A5D7`. Page background `#FFFFFF`, panels `#F8F8F8`, text `#191919`, muted text `#555555`, dividers `#CCCCCC`. Channels use a separate pastel set so they are never mistaken for brands. Replace these with the new project's palette.
- **Output:** the script writes `first_view.json` (and one parquet per table). The page only reads it.

## 3. Page layout

One scrolling page, sticky "On this page" menu on the left or top. Order:

```
[Badge: Pre-tagging view]
[Headline strip: 6 tiles]            <- summary 1 tiles
1. Coverage and data health          <- bar + coverage grid
2. Share of voice                    <- stacked bar + heatmap
3. Volume over time                  <- area chart + spike list
4. Ratings and engagement            <- rating bars + top-liked panel
5. What people talk about            <- keyword bars + phrase list
[Footer: how this was computed, filters applied, run date]
```

Section titles lead with the finding, generated by a template from the numbers (see each view). Each section: title, one-line takeaway, chart, sample-size strip, "Show data".

Mobile: single column; tiles wrap two per row; heatmap scrolls horizontally inside its own box.

## 4. The five views

### View 1: Coverage and data health

**Headline tiles (6):**
1. Items collected (after filters)
2. Sources (count of distinct `source`)
3. Brands (count of distinct `brand_std`, non-blank)
4. Date range (min to max) and months covered
5. Removed (giveaways + duplicates)
6. Data quality: % with date / % with rating / % with link (three small figures in one tile)

**Chart 1a: Items by source, split by lens**
- Type: horizontal stacked bar. One bar per `source`, sorted by total, largest at top.
- Segments: `lens` (max 4 colours). Value labels at the bar end.
- Click a bar: item list.
- Title template: `"<top source> supplies <x>% of the data; <n> sources in total"`.

**Chart 1b: Field completeness grid**
- Type: small table-heatmap, rows = `source`, columns = date, rating, likes, link, non-English.
- Cell = % of that source's items with the field. Colour ramp light to primary teal. A dash where the source has under 15 items.
- Purpose: tells the end user which later views a source can feed.

**Calculation:** `groupby(source, lens).size()`; completeness = `notna().mean()` per source; non-English = `lang_guess != 'en'`.

### View 2: Share of voice by brand and channel

**Chart 2a: Brand share, overall**
- Type: horizontal bar, one bar per brand, sorted descending. Value = item count, label shows count and %.
- Focal brand (if configured) in primary colour; others in one grey-blue.
- Exclude blank `brand_std`; show their count in the strip ("n items name no brand").

**Chart 2b: Brand × source heatmap**
- Type: heatmap. Rows = brands, columns = sources in a fixed order. Cell = item count; shade by the row's share of that column (so a quiet channel is still readable).
- Cell text: the count. Dash where the column total is under 15.
- A column where fewer than 2 brands reach 15 items gets a "not comparable" note under the chart.
- Click a cell: item list.

**Title template:** `"<brand> is <x>% of brand-named items; <y> of <z> channels cover 2+ brands"`.

### View 3: Volume over time

**Chart 3a: Items per month**
- Type: stacked area (or stacked column if under 24 months), x = month, y = items, stack = `lens`.
- Months with no items shown as zero, not skipped.
- Spike markers: a dot and short label on months above rolling median (6 months) + 2 × MAD. Maximum 3 labelled.
- Date range selector: last 12 months / all time. Default all time.

**Chart 3b: Last 12 months vs the 12 before**
- Type: small grouped bar, one pair per `lens`. Label shows % change; dash if the earlier base is under 15.

**Side list:** the spike months with count and the top source in that month.
**Title template:** `"Conversation peaked in <month year> (<n> items, <source> led)"`.
**Rule:** rows with blank dates are excluded here and the count is stated in the strip.

### View 4: Ratings and engagement

**Chart 4a: Average rating by brand**
- Type: dot plot (dot = average, line = 95% interval), brands on the y-axis sorted by average.
- Only brands with 15+ rated items. Others listed in a note with their count.
- Strip: `rated items only: n = <rated>, of <total>`.

**Chart 4b: Low-rating share by brand**
- Type: horizontal bar of % rated 1 or 2 stars (scale of 5), base 15+.

**Chart 4c: Median likes by source**
- Type: bar, sorted. Sources with under 15 items that carry likes are dropped with a note.

**Panel 4d: Most-liked items**
- Top 10 by `likes`: rank, text snippet, source, brand, likes, "open" link. Include a "Show next 10" button.

**Title template:** `"<brand> has the highest rating (<x> of 5) and <brand2> the lowest, on rated items only"`. If no brand passes the base, the title says ratings are too thin to rank.

### View 5: What people talk about (keywords, draft)

**Chart 5a: Topic hits**
- Type: horizontal bar. One bar per topic from an editable dictionary file `keywords.csv` (columns `topic`, `keyword`, `language`). Value = items matching at least one keyword; an item can match several topics.
- Hatch bars of 10 to 29; hide bars under 10 and list them in a note.
- Click a bar: item list with the matched keyword highlighted.

**Chart 5b: Topic by brand**
- Type: heatmap, topics × brands, cell = % of that brand's items matching the topic. Dash under 15 base.

**List 5c: Top phrases**
- Top 15 two-word and three-word phrases by frequency (stop words removed, phrases appearing in under 5 items dropped). Shown as a ranked list with counts, not a word cloud.

**Label on every chart:** "keyword-matched, draft". Title template: `"<topic> is the most mentioned topic (<x>% of items)"`.

## 5. Files the script should produce

```
first_view.json          all tile numbers, titles, chart series, notes
first_view_items.parquet filtered items (for click-through)
keywords.csv             topic dictionary, editable by the user
run_log.txt              rows in, rows removed (by reason), run time
```

## 6. Done when

- Running the script on the SG data gives the same item count the dashboard's Data & method tab shows for the pool.
- Every chart has a sample-size strip and a "Show data" block.
- No network call is made during the run.
- A second scrape with different brands and sources runs without code changes (only the column mapper is new).
